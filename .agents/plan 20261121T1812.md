# Implementation Plan - Allow Edit "Found cue data" Page (Issue #18)

## Overview
Implement GitHub Issue #18: `Allow edit "Found cue data" page`.
Allow users to directly edit the metadata in the "Found cue data" pane (`_foundDetailsTextView`) before applying it to the `.cue` file, or enter manual metadata when no search results are found.

## Proposed Changes

### 1. Core Parsing: `Core/CueFileParser.cs`
- Add `ParseFormattedText(string text, CueData? template = null)`:
  - Parses key-value lines formatted as `Field: Value` corresponding to the 11 metadata fields:
    - `Artist:` -> `Artist`
    - `Album:` -> `Album`
    - `Genre:` -> `Genre`
    - `Date:` -> `Date` (sanitizes 4-digit year)
    - `Label:` -> `Label`
    - `Cat No:` / `Catalog Number:` / `Catalog:` / `CatNo:` -> `CatalogNumber`
    - `Country:` -> `Country`
    - `Barcode:` -> `Barcode`
    - `Rel Date:` / `Release Date:` / `ReleaseDate:` -> `ReleaseDate`
    - `Discs: <discsStr>  Tracks: <tracksStr>` -> parses `DiscNumber`, `Discs`, `Tracks`
    - `Comment:` -> `Comment`
  - Preserves template fields (`OriginalLines`, `OriginalEncoding`, `DiscId`, `MusicBrainzDiscId`, `DiscogsId`, `Source`) if template is provided.
  - Returns a populated `CueData` instance.

### 2. UI Updates: `UI/MainWindow.cs`
- **Configure `_foundDetailsTextView`**:
  - Set `ReadOnly = false` so users can edit the text directly.
  - Set `AllowsTab = false` so `Tab` / `Shift+Tab` cycles focus between views rather than inserting literal tab characters.
  - Expose public property `public TextView FoundDetailsTextView => _foundDetailsTextView;` and `public TextView SourceDetailsTextView => _sourceDetailsTextView;`.
- **Keyboard Handling**:
  - In `_foundDetailsTextView.KeyPress`:
    - `Key.Enter` / `Key.CtrlMask | Key.Enter`: Calls `ApplyFoundCueData()` and sets `e.Handled = true` (preventing newline insertion and immediately saving/applying).
    - `Key.Esc`: Resets `_foundDetailsTextView.Text` to the unedited search result via `ResetFoundCueDataPreview()`.
  - In `Application.RootKeyEvent`:
    - Add guard: if `_foundDetailsTextView.HasFocus`, return `false` immediately so typing characters like 's' or 'd' does not trigger Deep Search or Diff Dialog.
- **Focus & Edit Preservation**:
  - Add `_lastPreviewedResultIndex = -1`.
  - In `UpdateResultPreview(bool force = false)`:
    - If `!force && _resultsListView.SelectedItem == _lastPreviewedResultIndex`, skip updating to preserve user edits when tabbing back from `_foundDetailsTextView` to `_resultsListView`.
- **Apply Logic (`ApplyFoundCueData()`)**:
  - Parse `_foundDetailsTextView.Text` using `CueFileParser.ParseFormattedText`.
  - Merge edited values into `_currentCueData`.
  - Enforce disc number validation (`DiscNumber = 1` if `Discs == 1` or `DiscNumber > Discs`).
  - Save file via `CueFileWriter.Save`.
  - Advance to next file in `_cueFiles` (or show completion dialog if at end).
  - Update `ResultsListView_OpenSelectedItem` and status bar `~Enter~ Apply` to call `ApplyFoundCueData()`.
- **Empty Search Results Support**:
  - When `_searchResults.Count == 0`, if `_foundDetailsTextView` gains focus while displaying `"(No results found)"`, populate with `FormatCueData(_currentCueData)` to allow immediate manual editing and saving.
- **Formatting Consistency**:
  - In `FormatCueData`, always include the `Comment: {data.Comment}` line so users see and can easily edit the Comment field.

### 3. Unit Tests
- Add comprehensive tests in `CueComplete.Tests/CueFileParserTests.cs` (or `MainWindowTests.cs`):
  - Test `ParseFormattedText` with full 11-field cue data.
  - Test `ParseFormattedText` with disc formats (`1 of 2`, `2`, empty tracks, etc.).
  - Test `ParseFormattedText` with alternate label keys and empty values.
- In `CueComplete.Tests/MainWindowTests.cs`:
  - Test `FoundDetailsTextView` has `ReadOnly == false` and `AllowsTab == false`.
  - Test editing `FoundDetailsTextView` and calling `ApplyFoundCueData()` saves changes.
  - Test `ResetFoundCueDataPreview()` reverts edits.
  - Test RootKeyEvent ignores 's' and 'd' when `FoundDetailsTextView.HasFocus`.

### 4. Build & Package
- Run `dotnet test` to verify all tests pass.
- Run `dotnet build -c Release`.
- Run `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true`.
