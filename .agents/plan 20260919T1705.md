# Plan: Add Comprehensive Exception Handling Across UI and Application Lifecycle

## Problem Summary
The user requested adding exception handling. Currently:
- Unhandled background task exceptions or domain exceptions can silently cause hangs, abrupt termination, or crash without diagnostics.
- `Application.Run` calls (for `openDialog`, `mainWindow`, and `dialog` in `MainWindow`) do not specify error handlers (`errorHandler`), meaning any exception during main-loop execution or modal dialog execution can cause unhandled crashes or modal loops to get stuck.
- `Application.MainLoop.Invoke` calls in `MainWindow.cs` lack exception handling, which can cause UI updates or log callbacks to fail silently or corrupt the main loop.
- If an exception occurs when saving a CUE file (`CueFileWriter.Save`) or parsing a CUE file (`CueFileParser.Parse`), there is no error dialog presented to the user.

## Implementation Strategy

1. **Global Exception Handling in `Program.cs`**:
   - Subscribe to `AppDomain.CurrentDomain.UnhandledException` to log fatal domain exceptions to `crash.log`.
   - Subscribe to `TaskScheduler.UnobservedTaskException` to capture and log unobserved background task exceptions.
   - Define a UI error handler callback (`HandleUiException`) and pass it to `Application.Run(openDialog, HandleUiException)` and `Application.Run(mainWindow, HandleUiException)`.

2. **Modal Dialog and UI Exception Handling in `UI/MainWindow.cs`**:
   - In `LoadCueFile`:
     - Wrap `CueFileParser.Parse` in a try-catch block with logging and `MessageBox.ErrorQuery`.
     - In `onLogHandler`, protect `Application.MainLoop.Invoke` delegate with try-catch.
     - In `Task.Run(...).finally`, protect `Application.MainLoop.Invoke` with try-catch, and guarantee `Application.RequestStop(dialog)` runs in a `finally` block so the modal dialog is always dismissed.
     - Pass an `errorHandler` lambda to `Application.Run(dialog, ...)` to log and safely dismiss the dialog if an error occurs.
   - In `ResultsListView_OpenSelectedItem`:
     - Wrap `CueFileWriter.Save` in a try-catch block to display a user-friendly `MessageBox.ErrorQuery` and log the error if saving fails.
