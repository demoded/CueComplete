# Plan: Order Search Results by Scoring (Issue #19)

**Date/Time:** 2026-11-22T08:22:00+13:00
**Issue:** #19 - Order "Search results" by number of tracks & metadata match
**Branch:** `feat/order-search-results-scoring`

---

## 1. Goal
Implement a scoring and ordering mechanism for release search results in `MetadataService` that ranks candidates based on metadata match with the verifying `.cue` file:
- Number of tracks match
- Barcode match
- Catalog number match (exact and partial)
- Country match
- Year / Date match
- Artist & Album match
- Disc & DiscNumber match

Score will be kept invisible in the UI (Option C), purely driving the ranking of search results so that the most relevant release (especially matching track count) is at index 0 and selected by default.

---

## 2. Weighting System

| Field | Condition | Weight |
| :--- | :--- | :---: |
| **Track Count** | `candidate.Tracks == source.Tracks` | **+35** |
| **Barcode** | Normalized numeric match (`candidate.Barcode == source.Barcode`) | **+35** |
| **Catalog Number** | Exact normalized alphanumeric match<br>Partial/substring match | **+25**<br>*(+15)* |
| **Country** | Matches via `StringExtensions.MatchesSourceCountry` | **+15** |
| **Year / Date** | Exact 4-digit sanitized year match | **+10** |
| **Artist** | Normalized artist match via `StringExtensions.MatchesArtist` | **+10** |
| **Album** | Normalized album match via `StringExtensions.MatchesAlbum` | **+10** |
| **Discs / Disc #** | Total discs match (+5) and/or Disc number match (+5) | **+10** |

---

## 3. Implementation Steps

1. **Model (`Core/Models.cs`)**:
   - Add `public int? Score { get; set; }` to `CueData`.

2. **Scoring Logic (`Core/ReleaseScorer.cs`)**:
   - Implement `ReleaseScorer.CalculateScore(CueData candidate, CueData source)`.
   - Implement normalized barcode comparison (strip non-alphanumeric/punctuation).
   - Implement normalized catalog number comparison (exact match +25, partial +15).
   - Evaluate track count, country, year, artist, album, and disc info according to the weighting table.

3. **Service Integration (`Core/MetadataService.cs`)**:
   - Implement `ScoreAndOrderResults(List<CueData> results, CueData sourceData)`.
   - Apply `ScoreAndOrderResults` before returning in fast search and deep search.
   - Preserves stable order when scores are tied.

4. **Unit Tests (`CueComplete.Tests/ReleaseScorerTests.cs` & `MetadataValidationTests.cs`)**:
   - Test each scoring component individually (tracks, barcode, catalog number, country, year, artist/album).
   - Test overall ranking: candidate with matching track count and catalog number outranks candidates with mismatched tracks.
   - Verify stability on tie scores.
   - Verify behavior when source has null/empty fields.
