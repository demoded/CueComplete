# Plan: Remove Discogs Search 5-Item Limit and Pre-filter by Artist

## Overview
In `DiscogsProvider.PerformDiscogsSearchAsync`, raw search results returned from the Discogs API (`GET /database/search`) were prematurely truncated to the first 5 items via `.Take(5)`. In cases where the query (e.g. catalog number, text search) returned more than 5 results and the desired release was positioned at or after the 6th item (e.g., Marco Garau's Magic Opera *Battle of Ice*, catalog number `MOG002`, which was at index 10 / 11th result), the target release was dropped before any artist/album matching took place.

## Proposed Changes
1. **`Core/Metadata/DiscogsProvider.cs`**:
   - Remove the `.Take(5)` limit from `searchResponse.Results`.
   - When `sourceData.Artist` is present, pre-filter `searchResponse.Results` by checking if any item's title (`"Artist - Album"`) matches `sourceData.Artist` via `StringExtensions.MatchesArtist`.
   - If matching candidates exist, restrict release detail fetches to only matching candidates. This avoids unnecessary API calls and avoids exhausting Discogs rate limits on irrelevant releases.
   - If no items match by parsed title or if `sourceData.Artist` is blank, process all candidates from `searchResponse.Results` without truncation.
2. **`CueComplete.Tests/StringComparisonTests.cs`**:
   - Add unit test `DiscogsProvider_CatNoSearch_FindsMatchBeyondFirst5Items` simulating a search returning 12 results where the target release is at index 10.
   - Assert that the target release is successfully returned and non-matching releases before it do not cause a drop.
3. **Verification**:
   - Run `dotnet test` to ensure all tests pass.
   - Run `dotnet build -c Release` and required publish commands.
4. **Progress Tracking**:
   - Document all steps in `.agents/progress.md`.
