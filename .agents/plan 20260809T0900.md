# Refactoring Plan: Modularizing `MetadataService.cs`

## Executive Summary
`Core/MetadataService.cs` has grown into a monolithic service (~730 lines) handling multiple distinct responsibilities:
1. High-level search orchestration & fast-search strategy logic.
2. Direct integration with the MusicBrainz API (using `MetaBrainz.MusicBrainz`).
3. FreeDB reverse lookup & HTML scraping.
4. Direct integration with the Discogs REST API (OAuth tokens/keys, JSON parsing, master tracklist heuristics, multi-disc position parsing, string cleaning).
5. Application-wide metadata logging and event dispatch.

This plan outlines splitting `MetadataService.cs` into modular, single-responsibility submodules located under `Core/Metadata/` and upgrading API/service response handling across ALL providers (MusicBrainz, FreeDB, and Discogs) to use strongly-typed C# models and deserialization instead of manual regex string extractions or untyped lookups.

---

## Target Submodule Architecture

```
CueComplete/
└── Core/
    ├── Metadata/
    │   ├── IMetadataProvider.cs        # Common contract for metadata providers
    │   ├── MusicBrainzProvider.cs     # Encapsulates MusicBrainz lookup & FreeDB parsing
    │   ├── DiscogsProvider.cs        # Encapsulates Discogs API calls & typed response parsing
    │   └── Models/                    # Strongly-typed DTOs for API responses
    │       ├── DiscogsSearchResponse.cs
    │       ├── DiscogsReleaseResponse.cs
    │       ├── DiscogsMasterResponse.cs
    │       ├── MusicBrainzReleaseDto.cs
    │       └── FreeDbLookupResult.cs
    ├── MetadataService.cs             # High-level orchestrator & public API entry point
    ├── CueFileParser.cs
    ├── CueFileWriter.cs
    └── Models.cs
```

---

## Key Requirement: Strongly-Typed Models & Deserialization Across All Providers

Instead of manual `JsonDocument`/`JsonElement` index inspection and raw regex string extraction:

### 1. Discogs Provider Models
Define C# records/classes with `[JsonPropertyName]` attributes representing Discogs API payloads:
* `DiscogsSearchResult` & `DiscogsSearchResponse`
* `DiscogsReleaseResponse` (including `DiscogsArtist`, `DiscogsLabel`, `DiscogsIdentifier`, `DiscogsTrack`, `DiscogsFormat`)
* `DiscogsMasterResponse` (including `Year`)

### 2. MusicBrainz & FreeDB Provider Models
Although primary MusicBrainz calls return SDK interfaces (`IRelease`), we standardize and isolate MusicBrainz data models:
* `MusicBrainzReleaseDto`: Strongly-typed intermediate DTO wrapping MusicBrainz release details, label info, genres, discogs cross-references, and track metrics.
* `FreeDbLookupResult`: Strongly-typed model for FreeDB lookup results (e.g. `ReleaseId`, `Title`, `SourceUrl`), replacing raw HTML regex scraping with structured response model parsing.

## Detailed Submodule Breakdown

### 1. `IMetadataProvider.cs`
**Namespace**: `CueComplete.Core.Metadata`  
**Responsibility**: Defines standard contract for provider queries and logging integration.
* **Interface Members**:
  * `string Name { get; }` (e.g., `"MusicBrainz"`, `"Discogs"`)
  * `Task<List<CueData>> SearchAsync(CueData sourceData)`

---

### 2. Provider DTO Models (`Core/Metadata/Models/`)
**Namespace**: `CueComplete.Core.Metadata.Models`  
**Responsibility**: Provide strongly-typed models for serializing/deserializing external API & service responses.
* **Discogs DTOs**: `DiscogsSearchResponse`, `DiscogsReleaseResponse`, `DiscogsMasterResponse`, etc.
* **MusicBrainz DTOs**: `MusicBrainzReleaseDto`, `FreeDbLookupResult`, etc.

---

### 3. `MusicBrainzProvider.cs`
**Namespace**: `CueComplete.Core.Metadata`  
**File Location**: `Core/Metadata/MusicBrainzProvider.cs`  
**Responsibility**: Encapsulates all MusicBrainz and FreeDB interaction using DTO models.
* **Responsibilities**:
  * Instantiate and manage `MetaBrainz.MusicBrainz.Query` client and `HttpClient`.
  * Perform primary MusicBrainz release searches (`SearchAsync`).
  * Execute FreeDB ID lookups (`GetReleaseIdsFromFreeDbAsync`) using `FreeDbLookupResult` model parsing instead of loose regex HTML parsing.
  * Map `IRelease` entities into `MusicBrainzReleaseDto` intermediate models before returning `CueData`.
  * Accept an `Action<string>? logCallback` for logging.

---

### 4. `DiscogsProvider.cs`
**Namespace**: `CueComplete.Core.Metadata`  
**File Location**: `Core/Metadata/DiscogsProvider.cs`  
**Responsibility**: Encapsulates all Discogs API communication and strongly-typed payload parsing.
* **Responsibilities**:
  * Store credentials (`_discogsKey`, `_discogsSecret`, `_discogsToken`) and manage authorization headers.
  * Execute direct release lookups (`SearchByReleaseIdAsync`), catalog searches (`SearchByCatalogNumberAsync`), and text searches (`PerformTextSearchAsync`).
  * Deserialize API payloads directly into DTO models (`DiscogsReleaseResponse`, `DiscogsSearchResponse`, `DiscogsMasterResponse`).
  * Map deserialized models to domain `CueData` objects.
  * Parse tracklists for multi-disc matching and heading detection using typed track models.
  * Provide utility helper `CleanDiscogsString(string? input)`.
  * Accept an `Action<string>? logCallback` for logging.

---

### 5. Refactored `MetadataService.cs`
**Namespace**: `CueComplete.Core`  
**File Location**: `Core/MetadataService.cs`  
**Responsibility**: Main orchestrator maintaining full backwards compatibility.
* **Responsibilities**:
  * Instantiates `MusicBrainzProvider` and `DiscogsProvider`.
  * Coordinates search workflow (`SearchReleasesAsync` logic: fast search -> prioritized Discogs search -> MusicBrainz search -> Discogs search/cross-enrichment).
  * Manages global logging setup (`IsLoggingEnabled`, static `Log` routing to `app.log` and `OnLog` event).
  * Preserves exact public constructor signature (`public MetadataService(string? discogsKey, string? discogsSecret, string? discogsToken)`).
  * Preserves static property `IsLoggingEnabled` and `OnLog` event.

## Step-by-Step Implementation Steps

1. **Create `Core/Metadata/` Directory & Abstractions**:
   * Create `IMetadataProvider.cs`.

2. **Create Strongly-Typed Response DTO Models**:
   * Create DTO classes/records in `Core/Metadata/Models/` for Discogs, MusicBrainz (`MusicBrainzReleaseDto`), and FreeDB (`FreeDbLookupResult`).

3. **Extract `MusicBrainzProvider.cs`**:
   * Move MusicBrainz lookup logic, `Query` initialization, and FreeDB scraping into `MusicBrainzProvider`.
   * Refactor FreeDB lookup and MusicBrainz mapping to use the new DTO models.

4. **Extract `DiscogsProvider.cs`**:
   * Move Discogs REST API calls and header formatting into `DiscogsProvider`.
   * Replace manual `JsonDocument` string/element parsing with `JsonSerializer.Deserialize<T>()` calls using the new DTO models.

5. **Refactor `MetadataService.cs`**:
   * Delegate provider calls to `MusicBrainzProvider` and `DiscogsProvider`.
   * Maintain top-level orchestration flow and log management.

6. **Build & Verify**:
   * Run `dotnet build` to ensure zero compilation errors or breaking changes in `Program.cs` / `UI/MainWindow.cs`.
   * Package single executable via `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true` as required by repo rules.

---

## Benefits
* **Complete Strong Typing**: Eliminates fragile manual string key lookups, untyped JSON navigation, and raw regex extractions across all providers.
* **Maintainability**: `MetadataService.cs` size reduced from ~730 lines to < 120 lines focused purely on orchestration.
* **Separation of Concerns**: MusicBrainz, FreeDB, and Discogs API details and DTO schemas are isolated into distinct submodules.
* **Testability**: Providers and DTO deserialization can be unit-tested independently.
* **Zero Breaking Changes**: Existing callers (`Program.cs`, `MainWindow.cs`) require no code modifications.
