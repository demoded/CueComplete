# Plan: Fix False Positive DISCNUMBER from Catalog Number and Enforce Deserialized Values

## Problem Summary
In `TestStubs/1994 - Blut [1994, Massacre, MASS CD 033, DE]/Atrocity - Blut.cue`, line 10 had `REM DISCNUMBER "33"`.
Investigation revealed:
1. **False Positive in `CueFileParser`**:
   The folder name is `1994 - Blut [1994, Massacre, MASS CD 033, DE]`.
   `CueFileParser.cs` used a regex `\b(?:CD|Disc)\s*(\d+)` across the entire folder name, which matched `MASS CD 033` (the catalog number) as disc number 33.
2. **Tracklist Prefix Bug in `DiscogsProvider`**:
   In `DiscogsProvider.cs`, track position regex `^([a-zA-Z]+|\d+)` turned purely numeric positions `1`, `2`, ... `15` into individual disc prefixes (`"1"`, `"2"`, ...), meaning each track was treated as a separate disc. As a result, `sourceData.Tracks` (15) never matched a single disc count, and `data.DiscNumber` was never populated.
   Furthermore, when `releaseObj.Formats` indicated a 1-disc release (`qty: 1`), `data.DiscNumber` was left null instead of being set to 1.
3. **Missing `DiscNumber` in `MusicBrainzProvider`**:
   `MusicBrainzReleaseDto` and `MusicBrainzProvider.MapToDto` mapped `Discs` and `Tracks`, but did not populate `DiscNumber` from `release.Media[i].Position`.
4. **Fallback in `MainWindow.cs`**:
   Because the search result's `DiscNumber` was null, `MainWindow.cs` merged `selectedResult.DiscNumber ?? _currentCueData.DiscNumber`, preserving the invalid `33` from the parser.
5. **No Sanity Check**:
   Neither `MainWindow.cs` nor `CueFileWriter.cs` validated `DiscNumber <= Discs`. A 1-disc release (`Discs == 1`) should never write `DISCNUMBER "33"`.

## Implementation Strategy

1. **`CueFileParser.cs`**:
   - Strip bracketed metadata `\[.*?\]` from `folderName` before searching for disc number patterns, preventing catalog numbers (e.g. `MASS CD 033`) from being matched as disc numbers.
   - If `data.CatalogNumber` is present and contains the candidate match, discard it.
   - Sanity check: If parsed `DiscNumber > 9` and no total discs > 9 are found, do not treat as disc number.

2. **`DiscogsProvider.cs`**:
   - Fix tracklist position parsing: For purely numeric positions (`1`, `2`, etc.), do NOT treat each number as a disc prefix. Numeric positions belong to `"Default"` / single disc.
   - When `data.Discs == 1` or format quantity is 1, set `data.DiscNumber = 1`.
   - In general, ensure `DiscNumber` is populated from strictly deserialized formats or matched media.

3. **`MusicBrainzProvider.cs` & `MusicBrainzReleaseDto.cs`**:
   - Add `DiscNumber` property to `MusicBrainzReleaseDto` and map it in `ToCueData()`.
   - In `MapToDto`, populate `DiscNumber`:
     - If `release.Media?.Count == 1`, set `DiscNumber = 1`.
     - If multiple media and `sourceData?.Tracks` is known, match medium by `TrackCount` and take its strictly deserialized `medium.Position`.

4. **`MainWindow.cs` & `CueFileWriter.cs`**:
   - Enforce consistency: If `Discs == 1`, `DiscNumber` must be `1`.
   - If `DiscNumber > Discs`, fallback to `1`.

5. **Test Stub Correction**:
   - In `TestStubs/1994 - Blut [1994, Massacre, MASS CD 033, DE]/Atrocity - Blut.cue`, update `REM DISCNUMBER "33"` to `REM DISCNUMBER "1"`.

6. **Unit Tests**:
   - Add unit tests in `CueComplete.Tests` covering:
     - `CueFileParser`: Folder with catalog numbers like `MASS CD 033` does NOT produce `DiscNumber = 33`.
     - `CueFileParser`: Folder with real disc number like `Album (CD 2)` produces `DiscNumber = 2`.
     - `DiscogsProvider`: Single disc releases with track positions `1..15` correctly set `DiscNumber = 1` and `Discs = 1`.
     - `MusicBrainzProvider`: Single disc releases set `DiscNumber = 1`.
     - `CueFileWriter`: Rejects `DiscNumber > Discs` when `Discs == 1`.
