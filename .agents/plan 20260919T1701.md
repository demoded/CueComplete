# Plan: Fix Application Hang Due to NetMainLoop Concurrency Race Condition

## Problem Summary
The application intermittently hangs and becomes completely unresponsive. Analysis of the process dump `CueComplete.dmp` revealed an unhandled `System.InvalidOperationException: Queue empty.` crash inside `Terminal.Gui.NetMainLoop.NetInputHandler()` caused by non-thread-safe concurrent access to `Queue<InputResult?>` between the background input worker thread and the UI thread's `MainIteration()`. Once the background input task crashes, the main thread hangs permanently inside `ManualResetEventSlim.Wait(-1)` waiting for console events.

This issue occurs because `Program.cs` explicitly sets `Application.UseSystemConsole = true;`, which forces `Terminal.Gui` to use `NetDriver` and `NetMainLoop` instead of the Windows-native `WindowsDriver` and `WindowsMainLoop`.

## Implementation Strategy

1. **Modify `Program.cs`**:
   - Remove `Application.UseSystemConsole = true;` from `Program.cs`.
   - Allow `Terminal.Gui.Application.Init()` to select the default platform driver on Windows (`WindowsDriver` / `WindowsMainLoop`), which uses native Win32 Console APIs without the race condition in `NetMainLoop`.

2. **Update `.gitignore`**:
   - Add `*.dmp` to `.gitignore` to avoid committing large memory dump files.

3. **Verification**:
   - Run `dotnet test` to ensure all existing tests continue to pass.
   - Run `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true` as required by project rules whenever building.
   - Log progress in `.agents/progress.md`.
