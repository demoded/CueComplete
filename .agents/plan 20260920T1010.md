# Plan: Fix MusicBrainz Artist Credit Resolution and Implement Track Count & TOC Verification

## Problem Summary
1. When searching for Flotsam & Jetsam's album *Saturday Night's All Right For Fighting*, the MusicBrainz search failed to find the exact release (`1048bd08-69a1-3a88-a337-adb125fe78c4`).
2. The CUE file contained track offsets which produced a calculated `MusicBrainzDiscId`. Because the release on MusicBrainz does not have any submitted DiscIDs, direct lookup returned 404.
3. The fallback Lucene search (`discid:<escapedDiscId>`) matched unrelated releases (such as "Q" by Mr. Children) due to punctuation tokenization in Lucene.
4. When looking up release details in `MusicBrainzProvider.cs`, `LookupReleaseAsync` was invoked without `Include.ArtistCredits`. Consequently, `release.ArtistCredit` was `null`.
5. In `MapToDto`, when `release.ArtistCredit` is `null`, it fell back to `fallbackArtist` (`sourceData.Artist`), overwriting the actual artist of unrelated releases with `"Flotsam & Jetsam"`.
6. This caused the false positive releases to pass the artist filter, and because `list.Count > 0`, the provider returned immediately without ever executing the text search (`artist:"..." AND release:"..."`) which would have matched `1048bd08-69a1-3a88-a337-adb125fe78c4`.

## Solution Strategy
1. **Pass `Include.ArtistCredits | Include.DiscIds` in all `LookupReleaseAsync` calls**:
   - Update `MusicBrainzProvider.cs` lines 60, 109, 168, and 249 to include `Include.ArtistCredits | Include.DiscIds`.
2. **Verify DiscID / Artist on Fallback Search Results**:
   - For results returned by the fallback Lucene search index (`FindReleasesAsync($"discid:{escapedDiscId} OR cdtoc:{escapedDiscId}")`):
     - Check if any disc in `release.Media` actually matches `sourceData.MusicBrainzDiscId`.
     - Verify artist matching using `StringExtensions.MatchesArtist(dto.Artist, sourceData.Artist)`.
     - Verify track count: If `sourceData.Tracks.HasValue && sourceData.Tracks.Value > 0`, ensure the release contains a medium matching the track count (or the total track count matches).
     - Do not fall back to `sourceData.Artist` for unknown/missing artist credit if it would allow false positive Lucene matches through.
3. **Fuzzy Track Count / Duration Matching**:
   - In `MapToDto` / search filtering, validate track count consistency between source CUE and candidate releases.
   - When DiscID lookup fails or yields no valid verified matches, fall through to FreeDB and text search.
4. **Unit Tests**:
   - Add unit tests simulating:
     - DiscID search returning a release with different artist (verifying it gets rejected).
     - DiscID search returning a release with different track count (verifying rejection).
     - Fallthrough to artist + album text query finding the correct release with matching track count.
5. **Build & Verify**:
   - Run `dotnet test`.
   - Run `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true`.
   - Update `.agents/progress.md`.
