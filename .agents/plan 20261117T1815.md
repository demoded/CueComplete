# Plan: Skip Non-Matching Search Fallback and Fall Back to Artist and Album Search

## Overview
When searching Discogs by Catalog Number (or general search where `sourceData.Artist` is specified), if none of the returned raw search results match the artist, the code previously fell back to taking all raw results (e.g. 50 items). This caused 50 concurrent release-detail HTTP requests to be dispatched for completely irrelevant releases, immediately exhausting Discogs API rate limits (60 req/min) and triggering `429 TooManyRequests` on subsequent queries.

## Proposed Changes
1. **`Core/Metadata/DiscogsProvider.cs`**:
   - In `PerformDiscogsSearchAsync`:
     - When `sourceData.Artist` is provided, filter `searchResponse.Results` to items matching the artist (or items where artist cannot be extracted from title).
     - If no items match the artist, do NOT fall back to all raw results. Skip launching detailed release requests for non-matching candidates.
   - In `SearchAsync`:
     - If `list.Count == 0` (even if candidate Discogs IDs or barcodes were queried but produced no valid matches), ensure text search by artist and album (and stripped title fallback) runs.
2. **`Core/MetadataService.cs`**:
   - In Fast Search (`!deepSearch`):
     - If Catalog Number search returns 0 matching results, fall back to searching Discogs by artist and album (with stripped title fallback if needed) before or as part of finding matches.
   - In Deep Search:
     - Do not re-run Catalog Number search if it already executed and produced 0 results during fast search.
3. **`CueComplete.Tests/StringComparisonTests.cs`**:
   - Add unit test verifying that when CatNo search returns results with 0 matching artist, 0 detailed release HTTP requests are fired.
   - Add unit test verifying fallback from 0-result CatNo search to artist and album search.
4. **Verification**:
   - Run `dotnet test` ensuring all tests pass.
   - Build in Release configuration via `dotnet build -c Release`.
   - Publish win-x64 single file executable via `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true`.
5. **Progress Logging**:
   - Record steps in `.agents/progress.md`.
