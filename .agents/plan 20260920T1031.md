# Plan: Fix MusicBrainz and Discogs Search for Annotated Titles and Catalog Numbers

## Problem Summary
In `app.log`, the search failed to find the existing Japanese MusicBrainz release `https://musicbrainz.org/release/92f9a500-1dfb-418e-9ed3-6dc01b392391` (Flotsam and Jetsam - *When the Storm Comes Down*, CatNo: `WMC5-78`, Country: `JP`, Barcode: `4988053600780`).
The search input from CUE was:
- Artist: `Flotsam & Jetsam`
- Album: `When The Storm Comes Down (Japan)`
- Catalog Number: `WMCP-78`

Root Causes:
1. **Title Suffix Pollution in Text Queries**:
   - `MusicBrainzProvider` queried `artist:"Flotsam & Jetsam" AND release:"When The Storm Comes Down (Japan)"`.
   - In MusicBrainz Lucene phrase search, `(Japan)` in the quoted release name causes 0 matches because the canonical title is `"When the Storm Comes Down"`.
2. **Discogs Text Fallback Skipped**:
   - In `DiscogsProvider.SearchAsync`, the text search fallback was conditioned on `string.IsNullOrWhiteSpace(sourceData.CatalogNumber)`. Because `sourceData.CatalogNumber` was `WMCP-78` (which returned 0 results on Discogs), Discogs never performed text search.
3. **Artist Name Normalization ('&' vs 'and')**:
   - CUE had `Flotsam & Jetsam` while MusicBrainz canonical artist is `Flotsam and Jetsam`.
   - `StringExtensions.MatchesArtist` didn't normalize `&` to `and`, which would cause results to be filtered out during post-search artist verification.
4. **MusicBrainz Catalog Number Search**:
   - `MusicBrainzProvider` didn't search MusicBrainz index by `catno:`. MusicBrainz Lucene index supports `catno:"..."` queries.
5. **Country Matching & Result Scoring**:
   - Japanese releases with `(Japan)` in the title or `JP` country should receive score bonus when ranking search results if country matches `JP`/`Japan`.

## Implementation Steps
1. **StringExtensions**:
   - Add `StripTitleAnnotations(string? title)` to remove trailing parenthetical/bracketed annotations (e.g. `(Japan)`, `[Deluxe Edition]`, `(Remastered)`).
   - Update `MatchesArtist` to normalize ` & ` and ` and ` (and `+`).
   - Add `MatchesCountry(string? country1, string? country2, string? titleContext = null)` to support scoring bonuses when country matches (e.g. `JP` <-> `Japan`).
2. **MusicBrainzProvider**:
   - In `SearchAsync`:
     - If `sourceData.CatalogNumber` is provided and no barcode is given, attempt catalog number search `catno:"..."` (or `artist:"..." AND catno:"..."`).
     - In text search, if the initial query with `sourceData.Album` returns 0 results, retry with `StripTitleAnnotations(sourceData.Album)`.
     - In result ranking, add scoring for country matches if country or album title annotations match the release country.
3. **DiscogsProvider**:
   - In `SearchAsync`, allow text search fallback even when `sourceData.CatalogNumber` is set if no results were found so far.
   - If initial text search returns 0 results, retry with `StripTitleAnnotations(sourceData.Album)`.
4. **Unit Tests**:
   - Add tests for `StripTitleAnnotations`.
   - Add tests for `MatchesArtist` with `&` vs `and`.
   - Add tests for MusicBrainz stripped album fallback and Discogs text fallback.
5. **Verification & Build**:
   - Run `dotnet test`.
   - Run `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true`.
   - Update `.agents/progress.md`.
